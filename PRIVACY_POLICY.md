## 3) Какие данные мы обрабатываем

### 3.1. Данные Telegram-аккаунта
- `tg_id` (Telegram user id)
- `tg_username` (если установлен)
- `first_name` / имя из Telegram
- идентификаторы чатов и сообщений (кнопки, таймеры, редактирование)
- для Mini App: `initData` / подпись WebApp для авторизации сессии

### 3.2. Данные профиля игрока (по вводу пользователя)
- имя и фамилия (если запрошены сценарием)
- игровой ник
- телефон (контакт Telegram или вручную)
- город / страна
- день рождения (опционально; можно пропустить)
- аватар (Telegram `file_id`, если синхронизирован)
- флаги согласия: `soglasie_offerta`, `soglasie_versiya`, `soglasie_data`
- отписка от приглашений: `otpis_priglasheniy`

### 3.3. Данные игры, вечера и статистики
- состав стола (ники, номера мест, привязка к профилю)
- роли (в режиме раздачи ботом или внесения ведущим)
- статусы (в игре / выбыл), фолы, голосования, фазы, таймеры
- результаты игр, победитель, баллы / рейтинг
- игровой вечер клуба: дата, состав вечера, номер игры вечера
- иммунитеты и бонусы (в т.ч. «игрок вечера»)

### 3.4. Данные клубов
- название клуба, владелец, город
- членство и роли: собственник / ведущий / игрок
- настройки клуба (таймеры, баллы, составы, брендинг)
- **анкета клуба** (`klub_ankety`): ответы собственника (объём игр, бюджет, команда, правила, контакты для связи) — для онбординга и поддержки

### 3.5. Анонсы
- тексты анонсов, дата/время/адрес
- записи игроков на анонс (`zapisi_na_anons`)

### 3.6. Картинки карт ролей и логотипы
Сохраняем идентификаторы файлов Telegram (`file_id`) и привязку к клубу/роли. Исходные файлы на своих дисках не храним без необходимости доставки.

### 3.7. Mini App
- авторизация через Telegram WebApp
- состояние игр/вечера, отображаемое ведущему и игроку
- проксирование аватаров, логотипов клуба и карт ролей по `file_id`

### 3.8. Логические бэкапы
Для восстановления на тарифе без PITR Сервис может хранить ограниченные логические снимки (`pm_logical_backups` и/или локальные JSON в `backups/`, папка в `.gitignore`).  
Срок хранения снимков ограничен (`BACKUP_KEEP`, по умолчанию около 7 суток для in-bot снимков).  
В снимках могут оказаться данные профилей, клубов, вечеров и активных игр, необходимые для восстановления сервиса.

### 3.9. Логи и диагностика
Технические ошибки и события (обработчик, код ошибки Telegram/Supabase). Мы не стремимся хранить содержимое произвольных сообщений вне сценариев ввода.
